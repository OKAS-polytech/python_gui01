# 1. 概要 (v2)
本ドキュメントは、「簡易メモアプリ」バージョン2の設計手順を定義するものである。MVCアーキテクチャの導入に伴い、コンポーネントベースの設計アプローチを採用する。

# 2. 設計思想
- **関心の分離 (Separation of Concerns)**: データ、UI、ロジックを明確に分離し、それぞれが独立して機能するように設計する。
- **単一責任の原則 (Single Responsibility Principle)**: 各クラスは、一つの責任のみを持つように設計する。例えば、`View`は表示に専念し、データ操作は行わない。
- **疎結合 (Loose Coupling)**: コンポーネント間の依存度を低く保つ。`Controller`が`Model`と`View`を仲介することで、`Model`と`View`が直接通信しないようにする。

# 3. 設計ステップ

### ステップ 3.1: データ構造の設計 (Memoクラス)
1.  まず、アプリケーションで扱う中核データである「メモ」がどのような情報を持つべきかを定義する。
2.  要件に基づき、`id`, `title`, `content`, `timestamp` の4つの属性を持つこととする。
3.  これらのデータを保持するためだけの、純粋なデータクラスとして`Memo`クラスを設計する。このクラスにはビジネスロジックを含めない。

### ステップ 3.2: データ永続化の設計 (Model)
1.  `Memo`オブジェクトをどのように永続化するかを設計する。要件に基づき、ファイルシステムへのテキストファイル保存方式を選択する。
2.  ファイルI/O（読み込み、書き込み、削除）の具体的なロジックを担当する`MemoModel`クラスを設計する。
3.  `MemoModel`は、`Memo`オブジェクトを受け取ってファイルに保存する`save_memo`メソッド、全メモファイルを読み込んで`Memo`オブジェクトのリストを返す`get_all_memos`メソッドなどを提供するインターフェースを定義する。

### ステップ 3.3: UIの設計 (View)
1.  ユーザーインターフェースの構造と振る舞いを設計する。外部設計書(v2)に基づき、UIの見た目はv1から変更しない。
2.  UIの構築と表示更新のみに責任を持つ`View`クラスを設計する。
3.  `View`は、UIウィジェットのインスタンスをプロパティとして保持する。
4.  外部（`Controller`）からイベントハンドラを受け取り、UIウィジェットにバインドするためのメソッド（例: `bind_save_button`）を定義する。これにより、`View`は「何をするか」を知らずに、「いつイベントが発生したか」だけを`Controller`に通知する。
5.  外部からデータを受け取り、画面を更新するためのメソッド（例: `update_memo_list`）を定義する。

### ステップ 3.4: ビジネスロジックの設計 (Controller)
1.  `Model`と`View`を協調させてアプリケーション全体の動作を制御する、`Controller`クラスを設計する。
2.  `Controller`は`Model`と`View`の両方のインスタンスへの参照を持つ。
3.  Viewから受け取ったユーザーのアクション（例: 保存ボタンのクリック）を解釈し、対応するビジネスロジックを実行する。
4.  ロジックの実行にあたり、必要に応じて`Model`にデータ操作を依頼する（例: `model.save_memo()`）。
5.  `Model`の操作によってデータが変更された後、`View`に画面の更新を指示する（例: `view.update_memo_list()`）。

### ステップ 3.5: 全体の組み立て
1.  `main.py`を、アプリケーションのエントリーポイント（起動処理）として設計する。
2.  `main.py`の責務は、`Model`, `View`, `Controller`の各コンポーネントをインスタンス化し、それらを互いに接続して、アプリケーションのメインループを開始することのみとする。
